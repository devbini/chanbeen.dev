## 들어가며
안녕하세요.  
최근에 프로젝트에서 **Vite 4를 Vite 7로 올리는 작업**을 하고 있습니다.

메이저 버전을 몇 개 건너뛰는 작업이라,  
사실 그냥 `npm install vite@latest` 하고 끝날 거라고 생각하진 않았습니다.  
그래도 처음부터 그렇게 이상한 곳에서 문제가 날 줄은 몰랐네요...

첫 번째로 마주한 문제는 **SVG 커서 이미지**였습니다.

![Vite 4에서 Vite 7 SVG Cursor URL 이슈](/11/1.png)
> 진짜 별 거 아닌 커서 하나 때문에 한참을 봤습니다...

원래는 특정 영역에서 resize cursor를 커스텀 SVG로 보여주고 있었는데,  
Vite 7로 올린 뒤 특정 페이지에만 들어가면 화면이 이상하게 깨지기 시작했습니다.

더 이상했던 건, 그 페이지에서만 깨지는 게 아니었다는 점입니다.  
문제가 되는 페이지에 한 번 들어갔다가 다른 페이지로 돌아가면,  
다른 페이지까지 HTML 구조가 무너진 것처럼 보였습니다.

처음엔 당연히 다른 문제인 줄 알았습니다.  
Vite 업데이트면 보통 plugin 문제라던지, 의존성 문제라던지,  
아니면 React 라우팅 쪽에서 뭔가 꼬였겠지 싶었거든요.

그래서 처음에는 페이지 이동부터 다시 봤습니다.  
특정 페이지에 들어가기 전까지는 멀쩡했고,  
그 페이지를 한 번 거치고 나면 다른 페이지까지 스타일이 깨져 보였습니다.

> 이거 DOM이 깨진 건가?  
> 아니면 CSS가 중간부터 안 먹는 건가?

돌고 돌아 보니, 결국은  
**Vite의 SVG asset URL 처리 방식**과  
**직접 조립해둔 `url(...)` 문자열**이 충돌한 케이스였습니다.

---

## 1. 문제가 된 코드

문제의 코드는 정말 짧습니다.

```tsx
import cursorImg from '@/assets/cursor.svg';

const resizeCursor = `url(${cursorImg}) 16, 16, col-resize`;
```

그리고 이 값을 이런 식으로 넣고 있었습니다.

```tsx
<div style={{ cursor: resizeCursor }}>
    ...
</div>
```

Vite 4에서는 이게 잘 동작했습니다.  
커서도 잘 보였고, 딱히 브라우저에서 문제를 뱉지도 않았던 걸로 기억합니다.

그래서 더 헷갈렸습니다.

> 아니, 이게 왜 갑자기 안 되지?

단순히 커서가 안 보이는 정도면 그냥 넘어갈 수도 있었는데,  
실제로는 CSS가 중간부터 제대로 적용되지 않는 것처럼 보였습니다.

그러다 보니 DOM이 깨진 건지, 라우팅이 꼬인 건지,  
아니면 스타일 로딩이 끊긴 건지 처음엔 구분이 잘 안 됐습니다.

UI에서 커서 하나 바꾸는 코드라고 생각했는데,  
결과적으로는 레이아웃 전체가 깨져 보이는 문제로 이어진 셈이죠.

---

## 2. SVG import 결과를 너무 단순하게 봤다

Vite에서 이미지나 SVG 같은 asset을 import하면,  
결과적으로는 브라우저가 접근할 수 있는 URL 문자열을 받게 됩니다.

저는 이걸 너무 단순하게 생각하고 있었습니다.  
대충 이런 경로가 들어오겠거니 했던 거죠.

```txt
/assets/cursor.abc123.svg
```

그런데 문서를 다시 보니,  
Vite는 asset 크기나 설정에 따라 작은 파일을 inline 처리할 수 있고  
그 경우 `data:image/svg+xml...` 같은 형태가 될 수도 있습니다.

![Vite SVG asset 처리 흐름](/11/2.png)
> SVG를 import했을 때 항상 깔끔한 파일 경로만 나온다고 보면 안 되겠더군요.

물론 이번 문제가 100% inline data URL 때문이라고 단정하긴 어렵습니다.  
다만 제가 만든 CSS 문자열은, `cursorImg`가 어떤 형태로 들어오든  
항상 안전하게 파싱될 거라고 가정하고 있었습니다.

> SVG asset URL이 어떻게 출력될지 모르는 상황에서,  
> 그 값을 따옴표 없이 `url(...)` 안에 그대로 넣고 있었다.

이 부분을 너무 단순하게 보고 있었던거죠.

---

## 3. 문제는 결국 문자열이었다

다시 기존 코드를 보면 이렇습니다.

```tsx
const resizeCursor = `url(${cursorImg}) 16, 16, col-resize`;
```

처음 봤을 때는 별 문제 없어 보입니다.  
사실 저도 이 코드가 문제일 거라고 바로 생각하진 못했습니다.

그런데 뜯어보니, 제가 CSS `cursor` 문법을 너무 느슨하게 쓰고 있었습니다.

### URL을 따옴표로 감싸지 않았다

단순 파일 경로라면 이런 CSS가 만들어집니다.

```css
cursor: url(/assets/cursor.abc123.svg) 16, 16, col-resize;
```

이 정도는 브라우저가 적당히 잘 읽어줄 수 있습니다.  
그래서 Vite 4에서도 별 문제 없이 넘어갔을 가능성이 큽니다.

그런데 SVG가 data URL 형태로 들어가거나,  
URL 내부에 특수 문자나 콤마가 섞이기 시작하면 이야기가 달라집니다.

```css
cursor: url(data:image/svg+xml;base64,...) 16, 16, col-resize;
```

여기서부터는 CSS 파서 입장에서 그리 친절한 문자열이 아닙니다.  
특히 data URL에는 콤마도 들어가고, SVG는 인코딩 방식에 따라 이것저것 섞일 수 있으니까요.  
그런 값을 `url()` 안에 따옴표 없이 밀어 넣고 있었던 겁니다.

나중에 Vite 문서를 다시 보니,  
JS에서 asset URL을 `url()`에 넣는 예시도 이런 식으로 되어 있었습니다.

```tsx
const background = `url("${imgUrl}")`;
```

아... 이거였구나 싶었습니다.

### hotspot 좌표도 이상하게 쓰고 있었다

그리고 하나 더 있었습니다.

```css
16, 16
```

커서 hotspot 좌표를 이렇게 콤마로 나누고 있었는데,  
`cursor`에서 URL 뒤에 붙는 좌표는 `x y` 형태로 공백을 사용합니다.

그래서 더 정확히 쓰면 이렇게 되어야 합니다.

```css
cursor: url("...") 16 16, col-resize;
```

그러니까 기존 코드는 두 가지 면에서 운 좋게 돌아가고 있던 코드였습니다.

- `url()` 안의 URL을 따옴표로 감싸지 않음
- hotspot 좌표를 `16, 16`처럼 적어둠

Vite 4에서는 넘어갔지만,  
Vite 7로 올라오면서 이 느슨했던 부분이 드러난 것 같습니다.

---

## 4. 해결은 좀 허무했다

결국 수정은 아래처럼 했습니다.

![SVG cursor URL 수정 전후 비교](/11/3.png)
> Before / After로 보면 정말 별 거 아닌데, 찾기 전까지는 꽤 헷갈렸습니다.

```tsx
import cursorImg from '@/assets/cursor.svg';

const resizeCursor = `url("${cursorImg}") 16 16, col-resize`;
```

변경점은 딱 두 가지입니다.

| 변경 전 | 변경 후 |
|:---|:---|
| `url(${cursorImg})` | `url("${cursorImg}")` |
| `16, 16` | `16 16` |

SVG URL을 큰따옴표로 감싸고,  
hotspot 좌표에서 콤마를 제거했습니다.

이렇게 바꾸니 Vite 7 환경에서도 정상적으로 동작했습니다.  
문제가 되던 페이지에 들어갔다 나와도 다른 페이지 레이아웃이 깨지지 않았고,  
CSS도 정상적으로 다시 적용되었습니다.

정말 코드만 보면 너무 허무한데,  
이런 류의 문제는 항상 그렇듯 원인을 찾기 전까지가 제일 오래 걸리는 것 같아요.

---

## 5. 그래서 얻은 교훈은?

처음에는 해결하고 나서도 조금 찝찝했습니다.  
커서 문자열 하나 때문에 화면 전체가 깨져 보였다는 게 잘 와닿지 않았거든요.

> 이게 Vite 7 문제인가?  
> SVG가 inline 되어서 생긴 문제인가?  
> 아니면 그냥 내가 CSS 문자열을 이상하게 만든 건가?

결론부터 말하면, 가장 직접적인 문제는 마지막에 가까웠습니다.  
Vite가 넘겨주는 asset URL을 제가 직접 CSS 문자열로 조립하고 있었고,  
그 문자열이 CSS 문법상 충분히 안전하지 않았던 겁니다.

특히 이런 코드는 겉으로 보면 별 문제가 없어 보입니다.

```tsx
const cursor = `url(${cursorImg}) 16, 16, col-resize`;
```

하지만 이 코드는 `cursorImg`가 어떤 모양의 문자열로 들어올지 너무 믿고 있습니다.  
단순 파일 경로면 넘어갈 수 있지만, data URL이 되거나 특수 문자가 섞이면  
갑자기 CSS 파싱이 꼬일 수 있습니다.

그래서 이번 문제에서 얻은 건 꽤 단순했습니다.

> 기술 문서를 볼 때, 예제 코드의 따옴표나 쉼표 같은 작은 문법도 그냥 넘기지 말자.

```tsx
const cursor = `url("${cursorImg}") 16 16, col-resize`;
```

Vite에는 `?url`, `?inline`, `?no-inline` 같은 방식도 있지만,  
이번 케이스에서 바로 필요한 해결책은 아니었습니다.  
우선 제가 만든 CSS 문자열부터 제대로 보는 게 맞았습니다.

그리고 하나 더 느낀 건,  
브라우저 콘솔에 친절한 에러가 크게 표시되지 않아도  
HTML 렌더링이나 CSS 적용에는 충분히 큰 문제가 생길 수 있다는 점이었습니다.

화면이 "HTML 구조가 깨진 것처럼" 보인다고 해서  
항상 DOM 구조나 React 컴포넌트부터 의심할 필요는 없겠더군요.  
스타일이 중간에서 끊기면, 결과적으로는 구조가 망가진 것처럼 보일 수 있으니까요.

---

## 마무리하며

이번 문제는 Vite 7 자체가 이상하다기보다는,  
기존 코드가 꽤 느슨하게 작성되어 있었고  
업데이트 과정에서 그 부분이 드러난 케이스에 가까웠습니다.

사실 이런 게 제일 애매합니다.  
코드가 완전히 틀린 것도 아니고, 예전에는 잘 됐으니까요.

그래서 다음부터 SVG나 이미지 asset을 CSS 문자열로 직접 조립한다면,  
최소한 실제로 어떤 문자열이 만들어지는지 먼저 찍어보고  
문서 예제의 문법도 조금 더 꼼꼼히 보려 합니다.

```tsx
const cursor = `url("${cursorImg}") 16 16, col-resize`;
```

결국 이번 이슈는 거창한 마이그레이션 이슈라기보다는,  
업데이트 과정에서 평소 대충 넘어갔던 CSS 문법이 드러난 케이스였네요.

다음 Vite 7 업데이트 이슈도 정리되는 대로 이어서 남겨보겠습니다.  
감사합니다. 😊
